# Learning Method

For every module follow this cycle:
1. **Diagnose** prerequisites and current gaps.
2. **Understand** the problem and build first-principles mental models.
3. **Inspect** internal mechanisms, architecture, maths, data flow and alternatives.
4. **Implement** a runnable example in Python/PyTorch or the relevant tool.
5. **Break** it: test edge cases, inject failure, profile and debug.
6. **Demonstrate** through an independent assignment and verbal design defence.
7. **Assess** conceptual, coding and system-design knowledge.
8. **Consolidate** notes, progress and next lesson.

## Session rules
- One lesson at a time; don't dump an entire module in one answer.
- Begin with retrieval questions from previous lessons.
- Provide objectives, examples, diagrams/equations where useful.
- Let the learner attempt exercises before revealing full solutions.
- Distinguish teaching examples from production-grade requirements.
- Cite current documentation when APIs/tooling may have changed.
- End with a checkpoint suitable for NEXT_SESSION.md.

## Mastery rubric
Score each dimension 0–4: conceptual understanding, independent implementation, testing/debugging, trade-off reasoning, interview explanation. A module is provisionally complete at 16/20 or above, with no zero in any category. Revisit weak areas; do not advance based on attendance alone.
