# Weekly Learning Schedule

**Target:** 15 focused hours per week outside existing work. Treat this as a sustainable target, not a mandate to sacrifice sleep.

| Activity | Hours / week | Suggested cadence |
|---|---:|---|
| DSA and coding | 5 | 1 hour × 5 days |
| Distributed systems | 3 | 3 × 1-hour sessions |
| AI systems engineering | 3 | 3 × 1-hour sessions |
| Project implementation | 3 | 2–3 focused blocks |
| System design / interview practice | 1 | 1 session |
| **Total** | **15** | |

## How to distribute the week
- On most weekdays, complete one DSA session and one focused learning block.
- Reserve longer blocks for implementation, debugging and benchmarking.
- Every week should produce at least one durable artifact: code, tests, a design note, an experiment or an assessment.
- Use a weekly review to rebalance based on actual workload and energy.

## DSA practice format
For a one-hour session:
1. Attempt a problem independently.
2. State a brute-force approach and complexity.
3. Improve the approach and explain why it works.
4. Implement and test edge cases.
5. Record the pattern and mistake in a log.
6. Revisit missed problems later; don't immediately count a viewed solution as mastered.

## Sustainability rule
If work becomes unusually demanding, reduce the weekly target rather than cutting sleep. Consistency over six months is more valuable than an unsustainable sprint.
